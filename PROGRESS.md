- **Last step done:** 002-S2, the conversation page at `/sessions/$sid` (`web/src/pages/Conversation.tsx`), built on the 002-S1 endpoints. It loads the whole conversation (pages of 1000 turns, fetched until every turn is in), keeps `Transcript.tsx`'s folded tool calls, also while Claude works, and has one "Show details" switch that unfolds tool calls and thinking in place of the old filter row. Approval and question cards sit after the last turn and answer through `/api/sessions/:sid/respond`. The reply box is at the bottom outside the scrolling area, with Stop beside it while Claude works (`/stop`) and the model and permission mode in the row under it (`/model`, new, and `/mode` when Claude runs here; otherwise used on the next send). A message you send shows at once until the transcript records it. The header names the conversation, links its project and shows Working, Waiting for you, Done or Stopped with an error. The "…" menu has Copy command for the terminal, subagent runs, Archive and Delete. `Live.tsx` keeps only the New session form (now posting `/api/sessions/new` and opening `/sessions/<id>`) and a redirect for `/live/<id>`; `/live?resume=<id>` redirects in the router; `/jobs/<id>` opens the conversation when the job has a session ID. Fixed the two 002-S1 problems: a send right after stopping a new conversation waits up to 8 s for the transcript the stopped Claude is still writing (resumes it once its size stops changing, or starts afresh under the same ID if none appears), and the transcript drops Claude Code's `<synthetic>` "No response requested." line. Checked in a browser on its own port: opened a finished claude-test conversation, sent a reply with Enter (answer appeared on the same page, same address), asked for a file in Ask-before-changes mode (approval card appeared, Allow once let Claude create it), Show details unfolded the tool call, the three old addresses landed on the conversation page, 390 px light and dark with no sideways scroll and no console errors.

- **How to run it:** open Control Center from Applications. After merging into `main`, run `bun run app` in the main checkout so the installed app gets the change. `bun run desktop` opens a development copy. For a browser check on its own port: `bun run build`, then `PORT=<free port> CC_APP_DIR=<empty folder> bun server/src/index.ts` and open http://127.0.0.1:<port>.
- **How to test it:** `bun run typecheck && bun run test && bun run build`. The session-ID endpoints, the model switch and the send-after-stop wait are tested with a stand-in for the Agent SDK in `server/test/api.test.ts` ("a conversation is addressed by its session ID"); the mid-turn message and the dropped "No response requested." line in `server/test/parsers.test.ts`. The page itself has no automated test; check it in a browser.
